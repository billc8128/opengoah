GOAH ARCHITECTURE · V2.1 · 2026-08-19

Goah

一个面向长期目标的 Agent Harness。单次 Agent runtime 负责推理和工具调用；Goah 负责把原始事实持久化、在崩溃后恢复执行，并在下一次唤醒时生成短而可信的工作上下文。

本文是当前产品与架构事实源，对应 Goah 0.4.x。北辰 Harness v0.10仅保留为历史方案。

1. 定位与边界

Goah 不替代 Pi、DeepSeek Harness 或其他单次会话 runtime。它位于会话之上，让一个目标可以跨进程、跨唤醒、跨 Agent 持续推进。
层回答的问题Goah 的责任
Turn Transcript模型这一轮看到了什么、调用了什么工具？定义标准事件；具体循环由 runner 实现
Execution谁应继续、何时继续、外部动作是否已发生？goal / wake / schedule / mailbox / action / handoff
Active Context下一轮模型此刻必须记住什么？从结构化状态确定性渲染短 Markdown

非目标：替用户判断什么行业指标重要；预设金钱预算；强制 Git/worktree；规定 token 或 wall-clock 上限；把所有目标都建模成软件项目。runner 可在本地电脑、云主机或其他进程环境执行，其文件与 Git 行为由 runner、模型或 skill 管理。

2. 三层架构

Ledger Kernel

通用 typed event、全局与流内顺序、append、replay、订阅、持久化和事务边界。不认识 Goal、Mail 或 Action。

Execution Modules

在内核上定义业务状态机与投影。默认组合提供长期目标执行所需的六个模块，但模块语义不进入事件内核。

Active Context View

把投影、handoff 和证据组合成短 Markdown。它是临时工作集，不是新的事实源。

runner / supervisor / connector
          │ facts
          ▼
ledger kernel ── append-only event streams
          │ fold + transactional projection
          ▼
execution modules ── goal / wake / schedule / mailbox / action / handoff
          │ deterministic composition
          ▼
active context text ── exact value captured by request.prepared
          │
          ▼
next model request

3. Ledger Kernel

3.1 事件信封

interface EventRecord {
  seq: number        // 全局单调顺序
  streamId: string   // wake:w1 / goal:g1 / metric:g1 / control:audit
  streamSeq: number  // 流内连续顺序
  ts: string
  actor: string
  type: string
  data: JsonValue
  ignorable?: true   // 仅纯信息事件可声明陌生 reader 安全跳过
}
  • seq 给出整个组织的一致历史；streamSeq 检测某个 Turn transcript 或 aggregate 是否缺事件。
  • 事件只追加；SQLite trigger 拒绝 update/delete。
  • 内核可批量追加；一个 batch 在同一事务内获得顺序。
  • 业务投影的 schema 与 projector 由执行模块拥有；内核没有固定 ProjectionName。

3.2 当前 SQLite 实现

一个 SQLite WAL 数据库、Supervisor 单写。物理上仍包含 events 和五张标准模块投影表：goals、schedule、wakes、mailbox、actions。事件是事实源，投影可重建；业务 mutation 在同一事务中追加事件并更新投影。

这一物理布局是默认组合，不是 Ledger Kernel 的公共类型系统。第三方内核实现只需满足事件顺序、追加、读取与事务契约。

4. Replayable Turn Transcript

每个 wake 默认拥有一个 wake:<id> Transcript stream。runner 的内部事件必须映射为 Goah 的稳定 vocabulary，不能把 Pi 私有对象结构直接当长期协议。

事件载荷与用途
transcript.startedrunner、provider、model 与能力
request.prepared实际 system prompt、Active Context、messages、tools、行为参数与来源 seq；永不记录 API key / authorization / signal
message.user进入模型表面的用户/合成输入
message.assistant.delta原始流式增量；用于流重放与取证
message.assistant.completed组装完成的模型消息；用于重建下一次模型历史
tool.called / tool.completed参数、结果与失败状态
context.compactedsummary、被替换与保留的 message id；原始消息不删除
transcript.completed / interrupted正常终止或恢复时关闭中断 transcript

replayTranscript() 从标准事件 fold 出模型可见的 Message[]。raw delta 不重复进入历史；assembled message 才是下一请求的消息节点。compaction 只替换当前 surface，原始事件仍可审计。

transcript.started.formatVersion 当前为 1。缺省版本按 legacy v0 在内存升级，不改写源事件；未来版本拒绝并要求升级 harness。Transcript namespace 中未知事件默认 required 并 fail-closed，只有显式 ignorable: true 的纯信息事件可跳过。

4.1 崩溃修复

若账本存在 tool.called 而 runner 在 tool.completed 前死亡，Supervisor 追加 synthetic tool.completed { outcome: "unknown" } 和 transcript.interrupted。它不声称工具未执行，也不盲目重放外部副作用。

5. Execution Modules

模块标准机制不属于模块的政策
Goalid / parentId / objective / owner / phase / revision；active/paused/blocked/complete 状态机、父层 authority 与 CAS强制 metric、target、金钱预算
Wakequeued / leased / running / done / abnormal / merge_blocked；lease fencing；同 Agent 并发 1任务 token/时长上限
Schedule到期生成 wake；触发去重与合并行业特定节奏
Mailboxdurable delivery；handoff 成功后才 ack组织结构与汇报制度
Actionrequested → approved → dispatching → confirmed/failed/unknown；unknown 对账哪些动作危险、金额或频率限制

Metric 是可选扩展：应用把 MetricContract 和 collector 注册给 Supervisor；Goal 本身不要求 metric。connector manifest 只声明幂等、查询、自动重试与通用风险级别，具体参数政策由应用拥有。

6. Active Context View

Active Context 不是模型每次重新总结，而是 Supervisor 的 ContextComposer 从结构化投影确定性生成。底层保持结构化，输出给模型的是短 Markdown。

# Objective
- [store] Open the store and obtain the first verified order.

# Wake
- Trigger: supplier reply

# Verified
- Supplier A can deliver within 48 hours. [event:182]

# Open
- Action create_storefront is unknown; reconcile before retrying.

# Next
- Confirm the return policy.

# Incoming
- [decision] Preserve at least 30% gross margin.

生成器返回 { text, sourceSeqs }。模型可在 handoff 中产生语义总结，但机械事实（Goal revision、未读 Mail、Action 状态）不能由模型改写。最终发送值由 request.prepared 记录，因此可以复现模型当时实际看到的上下文。

7. 进程与权限边界

  • Supervisor 是唯一 SQLite 写入方，常驻且不调用模型。
  • runner 每个 wake 一个短命子进程；不持有数据库连接和外部 connector 密钥。
  • runner 通过事件输出和受限 RPC 与 Supervisor 通信。
  • connector 在单独子进程运行，Supervisor 只下发该 connector 明确需要的密钥。
  • 本地或云端执行都由 runner 的 cwd 决定。Goah 不拥有 workspace/artifact/Git 生命周期。
  • 不引入消息队列、缓存或独立调度服务。

8. 故障语义

故障确定性结果
event 与投影之间崩溃同一事务整体回滚
runner 挂死滑动 lease 停止续约；Supervisor 终止记录 pid，wake abnormal
runner 中途退出保留全部已落 transcript 事件；未决 tool outcome 记 unknown
mail 装载后 wake 失败mail 仍未读；只在成功 handoff 事务内 ack
connector dispatching 时崩溃action 转 unknown；查询外部状态后 confirmed/failed
Supervisor 重启恢复 dispatching action 与过期 wake；不并发重放仍存活的 runner

恢复装载不展开上一 Turn transcript 的原始 delta 或 request snapshot；只选择 abnormal reason、interrupted/compaction 标记，以及 outcome unknown 的 tool call/result。完整流继续留在账本中供 Inspector 按需读取。

9. 包与代码边界

源码保留六个 workspace 的依赖边界，但 npm 只发布一个 @goah/cli tarball。五个内部模块作为 bundled dependencies 随包安装，避免一个逻辑版本产生六次发布。

源码模块公共入口职责
ledger-contract@goah/cli/kernel 等kernel、Transcript replay、execution 和 metric 契约
ledger-sqlite@goah/cli/sqliteSQLite schema v8、迁移、投影表与事务实现
supervisor@goah/cli/supervisor调度、lease、进程、connector、Active Context
runner-pi@goah/cli/runner-piPi 事件标准化、request snapshot、compaction 与进程协议

11. 当前完成度与限制

IMPLEMENTED IN 0.5 stream-aware required/ignorable event schema、v1–v8 SQLite 迁移、Transcript format v1 与 legacy upgrader、标准 Pi Transcript events、request snapshot、compaction replacement facts、Transcript replay、中断 tool unknown、带 textual Observation Method 的完整 Goal 生命周期、Active Context Markdown、Thread Inspector 与默认脱敏导出、可选 metric、现有 wake/action 故障语义。

NEXT 为非 Pi runner 发布 conformance suite；为海量 delta 增加批量 checkpoint 策略；用真实长跑账本继续检验 Active Context 的选择质量。

IMPLEMENTED CEO 作为唯一用户入口的组织运行层、原子 delegation/reassignment、派生 team roster、默认 Operating Policy、motion/revision 校验、交互式 goah shell、所有 Agent 的 Pi read/write/edit/bash 基础工具，以及持久 textual Goal Observation Method 见 CEO Agent Operating Layer。Milestone A–C、E 与确定性双 child canary 已实现；真实模型长跑仍属于运营验证。

Goah 保证状态机与证据链的机械一致性，不保证模型判断正确，也不把 prompt injection 防御伪装成账本能力。
