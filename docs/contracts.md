# Contracts

All public packages evolve in lockstep under `CONTRACT_VERSION`. The current contract is experimental; SQLite changes require an explicit version bump, future schemas are rejected, and pre-1.0 development workspaces may be recreated instead of migrated.

- Kernel: append-only typed events with global and per-stream order. Events are required by default; `ignorable: true` explicitly permits an unfamiliar reader to skip an informational event. The kernel does not name Goal, Wake, or Mailbox.
- Thread: model v1 owns durable Threads, Turns, and Turn Items. Turn transcript format v1 normalizes user/assistant/reasoning/tool/plan/Handoff facts. Turn source is `human|goal|system`; optional Goal binding is independent. Future formats and unknown required events fail closed.
- Execution modules: event and projection mutations are atomic. Thread/Turn/Item own conversation and execution state. Turn alone owns attempt, lease, fencing token, Runner PID/Profile, retry, terminal status, interruption, and recovery. Wake is `queued|claimed|consumed|cancelled` scheduling state and owns durable `pending|resolved` triggers with explicit `human|goal|system` source. `Wake.triggerRef` retains only the initial display/provenance value; Turn authority, recovery, redelivery, Runner admission, and Console state derive from the admitted trigger snapshots. Schedule is `pending|consumed|cancelled|superseded`; consuming it and creating or coalescing its Wake is atomic. Goal contains identity, hierarchy, objective, nullable Root observation/verification methods, ownership, phase, and revision. Every Goal mutation writes one authoritative `goal.changed` event. Private Ledger metadata names the projection while the typed event carries its single snapshot. Raw payloads may use arbitrary business fields but cannot write that metadata. Child Goals require both methods.
- Runner: process-isolated event protocol with Turn identity, source, optional Goal binding, normalized Item forwarding, fencing, exact request capture, and Runner-owned local execution. Supervisor owns Turn terminal status and Goal completion gates. Every Pi Agent receives `read`, `write`, `edit`, and `bash`; Goah RPC tools remain role-scoped.
- RPC: request/response IDs over the runner pipe; supervisor validates the active lease and role capability before every read or mutation. The interactive CLI uses a separate local control socket owned by the resident Supervisor, which remains the only SQLite writer.
- Load: structured projections are deterministically rendered as a short Markdown Active Context with source event sequences; the final value is recorded by `request.prepared`.
- Verification: a complete validated result is one immutable system Mail. Results with findings are decision-level, are delivered to the target Agent and escalated to CEO for child work, and share the same bounded unread/acknowledged context path in Human and Wake Turns.
- Work Record: one virtual Markdown document per Goal, stored as immutable versions plus a current projection. Organization-wide reads, history, diff, and search are available; owner/parent-owner updates use revision CAS and Ledger evidence. Goal-bound Turn completion requires a record version authored in that Turn.
- Handoff: ordinary Turns complete only through `finishTurn`; Goal-bound Turns complete only through `commitHandoff` after a current-Turn Work Record update. Goal Handoff is a Turn Item containing Goal/revision, Work Record revision, outcome, and evidence. Item, outgoing Mail, and optional Schedule are validated against one canonical TurnOutput before the atomic terminal commit.
- Legacy working memory: existing `memory:{agent}` streams remain readable and migrate into Work Records. CEO and Child Goal Agents no longer receive `memory.append`; verifier/audit memory remains independent.
- CEO operating layer: `ceo` is the sole normal Human-facing Agent. Human input starts/steers a Turn directly and never uses ordinary Mail or Wake. Durable Human intent may call `create_goal` or `work_on_goal`, after which strict Goal policy applies. Wake creates future Goal-bound Turns; Mail is asynchronous communication only.
- External effects: not part of the current contract. Ordinary tools and their permission prompts belong to the Runner. A future Connector layer must use a distinct optional contract and a real credential boundary rather than duplicating Tool Calls.

Third-party ledgers should run `assertLedgerConformance()` from `@goah/cli/testkit`. All public framework APIs ship in the single `@goah/cli` distribution; source workspace names are not independently published from 0.3 onward.
