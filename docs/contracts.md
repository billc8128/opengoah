# Contracts

All public packages evolve in lockstep under `CONTRACT_VERSION`. The current contract is experimental; SQLite changes require an explicit version bump, future schemas are rejected, and pre-1.0 development workspaces may be recreated instead of migrated.

- Kernel: append-only typed events with global and per-stream order. Events are required by default; `ignorable: true` explicitly permits an unfamiliar reader to skip an informational event. The kernel does not name Goal, Wake, or Mailbox.
- Thread: model v1 owns durable Threads, Turns, and Turn Items. Turn transcript format v2 normalizes user/assistant/reasoning/tool/plan/Handoff facts and content-addresses exact request components. Turn trigger is `user_message|wake`; optional Goal commitment is independent. Future formats and unknown required events fail closed.
- Execution modules: event and projection mutations are atomic. Thread/Turn/Item own conversation and execution state. Turn alone owns attempt, lease, fencing token, Runner PID/Profile, exact Goal revision, retry, terminal status, interruption, and recovery. Wake is `queued|claimed|consumed|cancelled` scheduling state, optionally targets a `goalId`, and owns durable `pending|resolved` triggers with explicit `human|goal|system` source. `Wake.triggerRef` retains only the initial display/provenance value; Turn authority, recovery, redelivery, Runner admission, and Console state derive from the admitted trigger snapshots. Wake and Schedule do not freeze Goal revisions: admission resolves the current active owner and revision. Schedule is `pending|consumed|cancelled|superseded`; consuming it and creating or coalescing its Wake is atomic. Goal contains identity, hierarchy, objective, nullable Root observation/verification methods, ownership, phase, and revision. Every Goal mutation writes one authoritative `goal.changed` event. Private Ledger metadata names the projection while the typed event carries its single snapshot. Raw payloads may use arbitrary business fields but cannot write that metadata. Child Goals require both methods.
- Runner: process-isolated event protocol with Turn identity, source, optional Goal binding, normalized Item forwarding, fencing, exact request capture, and Runner-owned local execution. Supervisor owns Turn terminal status and Goal completion gates. Every Pi Agent receives `read`, `write`, `edit`, and `bash`; Goah RPC tools remain role-scoped.
- Live output: `emitLive` carries minimal assistant deltas with a stable message ID into an in-memory `TurnLiveSnapshot`; it never appends Ledger events. Durable `emit` carries completed messages/reasoning, tools, compaction, and terminal facts. Provider cumulative `partial` objects are forbidden from the live protocol.
- RPC: request/response IDs over the runner pipe; supervisor validates the active lease and role capability before every read or mutation. The interactive CLI uses a separate local control socket owned by the resident Supervisor, which remains the only SQLite writer.
- Load: structured projections are deterministically rendered as a short Markdown Active Context with source event sequences. `request.component` stores each distinct system prompt, Active Context, message and toolset once; `request.prepared` references hashes so exact requests remain replayable without quadratic duplication.
- Verification: a complete validated result is one immutable system Mail. The Verifier model selects its `high|normal|low` delivery priority as part of the structured result; Supervisor validates and preserves that choice without inferring severity from the finding count. Results are delivered to the target Agent and escalated to CEO for child work through the same bounded unread/acknowledged context path in Human and Wake Turns.
- Work Record: one virtual Markdown document per Goal, stored as immutable versions plus a current projection. Organization-wide reads, history, diff, and search are available; owner/parent-owner updates use revision CAS and Ledger evidence. Committed Turn completion requires a record version authored in that Turn. A parent may complete a Child only when the current owner authored its current-revision Work Record in a completed Turn and the completion evidence cites that record or matching Handoff.
- Response/Handoff: every successful Runner result returns `finalMessageId`, never duplicate prose. Uncommitted Turns atomically commit that readable Assistant Item through `commitTurnResponse`; committed Turns use live `goal.handoff.validate` before `commitHandoff`. Every attempt binds the same message Item, invalidates prior tokens, and returns an `attemptId`; correctable issues must be delivered through required Runner-session feedback, while authority/fencing loss revokes the Turn and blocks remaining tools. `TurnOutput` carries the current accepted attempt/token plus declarative `outcome + evidence`; `response.committed` is the canonical response pointer. Normalized message events declare `commitState`. Tokens deliberately omit Work Record revision so an Agent may refine its record after validation; commit injects the final revision.
- Mail: the envelope owns typed Goal, CEO-inbox, or Specialist-inbox routing; arbitrary `body` fields never affect admission. `mail.send` addresses Agents only. Human communication exists solely as canonical User/Assistant Messages in the CEO Thread.
- Legacy working memory: existing `memory:{agent}` streams remain readable and migrate into Work Records. CEO and Child Goal Agents no longer receive `memory.append`; verifier/audit memory remains independent.
- CEO operating layer: `ceo` is the sole normal Human-facing Agent. Human input starts/steers a Turn directly and never uses ordinary Mail or Wake. Every CEO Turn sees the active Root Goal as advisory context. Durable Human intent may call `create_goal` or `work_on_goal`, after which a Goal commitment activates strict policy. Wake creates future committed Goal work; Mail is asynchronous communication only.
- External effects: not part of the current contract. Ordinary tools and their permission prompts belong to the Runner. A future Connector layer must use a distinct optional contract and a real credential boundary rather than duplicating Tool Calls.

Third-party ledgers should run `assertLedgerConformance()` from `@goah/cli/testkit`. All public framework APIs ship in the single `@goah/cli` distribution; source workspace names are not independently published from 0.3 onward.
