- The retry Active Context cited the prior handoff and recovery evidence and completed Phase 2 without repeating Phase 1.

## Findings fixed during the run

1. The first canary showed that raw model options placed an API key in `request.prepared.modelConfig`. The run stopped immediately. Request snapshots now use a strict behavior-only allowlist; API keys, authorization values, abort handles, and transport-private objects are excluded. A regression test enforces this.
2. The clean retry showed that recovery context expanded every raw event from the failed wake, producing 107,947 characters. Recovery selection now keeps only the abnormal reason, interrupted/compaction markers, and tool call/result pairs whose outcome is unknown. Applied to the same real failed stream, the selection fell from 118 events to 4 and the recovery view from 107,947 to 730 characters.
3. Positional CLI parsing failed when `--config` appeared before a wake ID. Inspector commands now ignore option/value pairs while resolving positional arguments.
