Goah CEO Agent Operating Layer用户入口、组织运行协议与机械保证

本文定义 CEO Agent 如何作为 Goah 的唯一正常用户入口，将人类意图转换为持久 Goal 树，组织短命 Agent，检查证据，并在跨 Thread、跨时间运行中维持组织连续性。

IMPLEMENTED / A–C, EPRODUCT ARCHITECTURE 0.42026-08-20
ARCHITECTURAL DECISION
CEO 不是常驻进程，而是每次 wake 时由 Ledger 重建的持久身份。模型负责开放式组织判断；Supervisor 和 SQLite 负责状态转换、原子性与恢复语义。
01 · Product contract

交互式 CEO 与权限边界

正常体验应与 Codex / Claude Code 一致：用户在当前目录运行一个命令，进入持续的 CEO 对话；Goal、Wake 和 child 名称仍是可检查的内部概念。

primary entryINTERACTIVE CEO
goah
goah "Launch a profitable store"
goah --continue
IMPLEMENTED IN 0.5.0
交互式 shell 会启动或连接 resident Supervisor；所有用户写操作通过本地 control socket，由 Supervisor 作为唯一 SQLite writer 提交。低层 goal/ceo 命令继续作为自动化与运维接口。
PURPOSE AUTHORITY

Human controls why.

创建、修订、暂停、恢复、完成 root Goal。root 的执行 owner 是 CEO，但目的层永远属于人类。

↔
METHOD AUTHORITY

CEO controls how.

拆解 descendants、委派 ownership、重组团队。只能推荐 root completion，不能替人类完成根目标。

Universal work surface

所有 Agent 的 Pi 基础工具

组织角色只限制 Goah 控制工具，不应剥夺普通工作能力。CEO 和每个 child 默认拥有同一套本地工作基础设施。

read读取项目文件和既有材料
write创建完整文件与 artifact
edit进行有边界的局部修改
bash枚举目录、搜索、执行脚本、测试和本地 CLI
FILESYSTEM-FIRST DISCOVERY
Agent 使用 Bash 和文件工具读取当前目录、`goah.config.json`、脚本与非敏感 manifest。无需为了镜像可读配置而增加 capability / connector / metric 发现 RPC；Ledger 查询和受保护写入仍通过 Supervisor RPC。
02 · Durable evaluation contract

Goal Observation Method

Objective 描述要实现什么；Observation Method 描述每次 wake 必须如何观察现实、判断进展与完成。它是一段持久 Markdown，类似每个 Goal 专属的微型 Skill。

ROOT GOAL

CEO proposes; human confirms.

新 root 从 null 开始。CEO 先探索项目、口径和数据来源，再提交 observation method 给用户确认。非空 root method 只能由 human authority 写入。

CHILD GOAL

CEO writes the pair.

Delegation 必须同时写 objective 与非空 observation method。修改 child objective 时，必须在同一 revision 中替换 method。

Root onboarding protocol

第一次 wake 先建立可靠观测

Inspect locally

用 read、edit、write、bash 检查 cwd、项目文档、代码、脚本、本地 CLI、配置与已有 Ledger 证据。

Clarify success

确认目标约束、当前 baseline 与“完成”的实际含义，不把自然语言中的歧义当事实。

Define observation

对定量或外部结果明确 source、计算口径、freshness、cadence、时区、持续周期和缺失数据行为。

List access

说明每个数据源和子目标需要的权限；无法从项目发现的部分才请求用户。

Explore safely

等待确认时仍可开展安全、可逆的调查；探索 child 也必须有自己的 observation method。

Confirm

CEO 发送草案，用户确认后由 human authority 写入 root projection 并增加 revision。

Hold the definition

每次 CEO/child wake 强制装载当前 method；完成必须引用按该方法产生的 Ledger evidence。

05 · Runtime policy

CEO Operating Policy 与触发条件

开放式判断留给模型；组织变化只通过可审计、高层、原子工具生效。

Orient

读取 root、Goal tree、每个 observation method、roster、mail、handoffs、blockers、unknown actions 与 previous plan。

Diagnose motion

逐个 Goal 判断是否在运行、排队、计划或等待，以及 owner 是否仍按权威 observation method 工作。

Decide organization

保持、delegate、revise objective/method、reassign、pause、complete、merge，或者升级给人类。

Apply decisions

只使用高层原子工具；不允许用多个低层调用模拟 delegation。

Ensure motion

每个 active child 必须有非空 method，以及 wake、schedule、wait trigger 或已升级 blocker。

Close the loop

声明下一次 review、等待触发、人类 blocker，或提交 completion recommendation。

Invalid exitroot 仍 active，但 CEO handoff 无 delegation、无 schedule、无 wait、无 blocker。

07 · Safety properties

机械不变量与故障语义

CEO 可以判断错，但不能让错误判断绕过组织状态机或在 wake 之间悄悄更换成功定义。

C1只有 human authority 可修改或完成 root Goal。
C2delegation 原子提交 Goal + mail + wake。
C3每个 active child Goal 必须有 owner。
C4每个 active child 必须有 liveness route 或 blocker。
C5CEO 不得留下 motionless active root。
C6child terminal / blocked / exhausted 必须 wake CEO。
C7complete Goal 不再接受自动 wake。
C8roster 从 facts 推导，不信模型自述。
C9重复 delegation ID 不产生重复工作。
C10CEO recommendation 永不获得 root authority。
C11每个 delegated child 必须有非空 textual observation method。
C12root method 非空只可能来自 human authority。
C13修改 objective 必须同步替换或失效 method。
C14Goal completion 引用当前 method 下产生的 Ledger evidence。
C15每个 Agent 都有 read / write / edit / bash；role 只限制 Goah 控制工具。
CEO_CRASH_PRE_COMMIT无组织变化。
CEO_CRASH_POST_COMMITGoal / mail / wake 全部存在；重试幂等。
CHILD_RETRY_EXHAUSTED触发 CEO，携带 abnormal reason 与最后 durable handoff。
MOTION_INVALID拒绝 handoff，注入 violation 重试；重复失败升级 human。

Open questions

Q1

多个 root Goals 共用一个 CEO？Initial: one CEO, Active Context grouped by root.

Q2

child 可以继续 delegate？Initial: no. Nested delegation comes later.

Q3

profile templates 进入 Ledger？Initial: deployment config owns templates; wake records resolved name.

Q4

每个 child handoff 都 wake CEO？Initial: terminal/material immediately; routine work coalesces into review.

Q5

root objective 修改后是否总是清空 method？Initial: clear by default; human may explicitly reconfirm an unchanged method.

Q6

交互式 shell 如何连接 resident Supervisor？Initial: one local Unix socket or platform equivalent; no separate scheduler service.
